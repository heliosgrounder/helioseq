# Changelog

All notable changes are documented here. This project follows
[Semantic Versioning](https://semver.org/).

## 0.1.0 — unreleased

First release. helioseq starts as a toolkit rather than a single-purpose
library: `seq`, `seqio`, `stats`, `motifs` and `shuffle` are separate domains
under one package, layered so that a new domain is a local addition.
[`docs/architecture.md`](docs/architecture.md) states the contract, and
`tests/test_package.py` enforces it by reading the import graph.

### helioseq.seq

- Sequence type handling: every public function in the toolkit accepts `str`,
  `bytes`, `bytearray` or `memoryview` and returns the input's type.
- DNA/RNA/protein alphabets with detection and validation. Errors name the
  offending character and its position.
- NCBI translation tables 1, 2, 4 and 11; `translate`, `split_codons`,
  `codon_counts`.
- `complement`, `reverse_complement` (IUPAC-aware, case-preserving),
  `composition`, `gc_fraction`.

### helioseq.seqio

- Streaming FASTA and FASTQ readers and writers, no dependencies. Constant
  memory regardless of file size.
- gzip, bzip2 and xz detected from magic bytes rather than the file extension.
- `read_sequences` / `write_record` dispatch by format; adding a format is two
  entries in a table.

### helioseq.stats

- `null_test` / `null_distribution` with an empirical p-value that uses the
  add-one correction, so it is never reported as `0`; `resolution` and
  `at_resolution_limit` say when a result sits at the floor of what `n` shuffles
  can measure.
- `constant_null` catches the common vacuous test — a statistic the null model
  preserves by construction, such as GC content against a `k >= 2` shuffle.
- `normality_warning` flags a null too skewed for the z-score to mean anything.
- Ready-made statistics: GC content, CpG observed/expected, k-mer frequency,
  longest homopolymer. Any callable works.
- Threaded evaluation, with results independent of thread count.

### helioseq.motifs

- Position weight matrices as plain lists of `{residue: score}` mappings.
- `from_counts` (counts to log-odds with a pseudocount and a configurable
  background), `consensus`, `scan`, `best_score`.
- `best_score` returns a statistic, so motif enrichment against a
  composition-matched background is one `null_test` call.

### helioseq.shuffle

k-let preserving shuffling, from
[uShuffle](https://doi.org/10.1186/1471-2105-9-192) (Jiang, Anderson, Gillespie
& Mayne, *BMC Bioinformatics* 2008, 9:192 — **please cite it**). The algorithm
is theirs; the implementation is a rewrite.

- `shuffle`, `Shuffler`, `shuffle_many`, `shuffle_batch`, `set_seed`.
- `klet_counts`, `klets_preserved`, `check_klets`, and degeneracy diagnostics
  (`is_degenerate`, `diagnose`) for the case where every "shuffle" returns the
  input.
- `shuffle_masked` keeps `N` runs and soft masking in place; `shuffle_windows`
  and `shuffle_segments` shuffle locally instead of globally.
- `codon.shuffle_codons`, `codon.shuffle_synonymous`,
  `codon.shuffle_third_positions` — frame-aware null models for CDS.
- `ml.dinuc_shuffle` with the `deeplift` signature, one-hot helpers, and a
  threaded batch API. NumPy is optional and imported only here.

#### What the rewrite fixes, relative to `ushuffle` 1.1.2 (2020)

- **Installation.** The extension is handwritten C against CPython's limited
  API, so one `cp39-abi3` wheel per platform runs on 3.9 through 3.14 and every
  version after it. There is no code generation in the build. 1.x shipped C
  generated by Cython 0.29.5, which stopped compiling on 3.11 (`Py_SIZE()`
  ceased to be an lvalue, guma44/ushuffle#10) and on 3.12 (`longintrepr.h` left
  the public headers, guma44/ushuffle#13) — and shipped no wheels, so every
  install had to compile it.
- **`pip install` cannot fail on a missing compiler.** The pure-Python fallback
  produces byte-identical results. `HELIOSEQ_REQUIRE_EXTENSION=1` makes a failed
  build fatal; the wheel jobs set it.
- **Two live shufflers no longer corrupt each other** (guma44/ushuffle#7). 1.x
  kept the sequence, its length, `k` and the whole graph in file-scope statics,
  so preparing a second sequence invalidated the first and wrote past the
  caller's buffer. Reproduced under AddressSanitizer; now covered by a
  regression test.
- **No dangling pointers.** The context owns a copy of the sequence; 1.x stored
  a `char *` into a temporary `bytes` object and dereferenced it later.
- **`str` input works** (guma44/ushuffle#4), and embedded `NUL` bytes no longer
  truncate the sequence (1.x used `strlen()`).
- **Out of memory raises `MemoryError`** instead of calling `exit(1)` and
  killing the interpreter.
- **The random source is no longer platform-dependent or biased.** 1.x used
  `random()` — or `rand()` on Windows, where `RAND_MAX` is 32767, so
  Fisher-Yates could not reach indices above that at all, silently non-uniform
  for sequences over ~32 kb — with `x % n` for bounded values. Replaced with a
  bundled xoshiro256++ and exactly unbiased masked rejection sampling.
- **Per-object seeding** (guma44/ushuffle#12), reproducible across platforms and
  Python versions. Thread-safe, with the GIL released so threads scale.
- Peak memory during analysis is down from roughly 60 to roughly 42 bytes per
  input base.

### helioseq.cli

- `helioseq shuffle | check | klets | null | info`, also `python -m helioseq`.
- One module per subcommand behind a registry; shared flags (`-i`, `-o`, `-k`,
  `--seed`, `--quiet`) are defined once so they mean the same thing everywhere.
- Command modules import their domains inside `run()`, so `helioseq klets` never
  loads the shuffling extension or NumPy.

### helioseq.compat

- `helioseq.compat.ushuffle` reproduces the `ushuffle` 1.x API for migration,
  with the bugs fixed. Output therefore does not match 1.x for a given seed — it
  could not, since 1.x used the platform's `rand()`.
